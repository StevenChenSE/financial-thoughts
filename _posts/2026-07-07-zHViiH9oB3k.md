## A Practical Guide to Hierarchical Delegation and Local AI Workflows

### Introduction
Building artificial intelligence agents from scratch is one of the most effective ways to transition from passive consumer to active developer. This guide walks through the design, implementation, and evaluation of a deep research agent built entirely on local hardware. The system runs on an AMD Ryzen AI CPU paired with a Strix Halo integrated GPU, alongside a discrete AMD Radeon AI PRO R9 7000 GPU. Throughout the development process, the Qwen model family is utilized to power both the coding assistant and the final agent deployment. Rather than relying on pre-packaged solutions, this approach emphasizes understanding the underlying architecture so you can adapt the workflow to any custom agentic task.

### The Context Pollution Problem in Flat Agents
The most straightforward way to build a research agent is a single flat architecture equipped with two tools: a web search tool (like DuckDuckGo or Tavily) and a URL fetcher that converts web pages into text. While functional for simple queries, this design quickly fails as tasks scale. Every tool output, intermediate reasoning step, and fetched document permanently accumulates in the LLM's context window. A single web page can consume thousands of tokens, and irrelevant or partially relevant content dilutes the signal the model needs to focus on.

This context accumulation triggers two critical failures:
1. **Performance Degradation:** As context approaches 64K tokens, prompt processing and token generation rates drop significantly on local hardware.
2. **Quality Degradation:** The model must attend to massive amounts of noisy text, making it harder to extract accurate information and increasing the likelihood of hallucination or missed details.

### Implementing a Three-Tier Delegation Strategy
To solve context pollution, delegation is far more effective than periodic context compression. Instead of one agent handling everything, a hierarchical architecture splits responsibilities:

* **Orchestrator:** Breaks the user query into focused research angles and delegates each to a searcher. It never sees raw intermediate steps, keeping its context clean for report generation.
* **Searcher Sub-Agent:** Receives a specific query, runs web searches, and fetches pages directly to disk. It does not read full documents into memory.
* **Page Analyzer Sub-Agent:** Takes fetched files and uses targeted extraction tools rather than ingesting entire documents. By leveraging a `grep` tool to find relevant patterns and a read tool to pull only necessary line ranges, the analyzer maintains a tightly focused context. Semantic search can also be integrated alongside pattern matching for complex retrieval tasks.

This three-tier structure ensures that raw data never pollutes the orchestrator's context, and each sub-agent operates within a clean, purpose-built environment.

### Preventing Infinite Loops with Tool Quotas
Autonomous agents can easily enter repetitive loops, repeatedly calling the same search tool or fetching identical pages until the context limit is reached. To mitigate this, a dual-layer quota system is implemented:

* **Hard Caps (Harness Level):** The execution framework strictly counts tool invocations. Once a limit is hit, the call is blocked and an error is returned, preventing runaway token consumption.
* **Soft Layer (Prompt Injection):** Quota values are injected directly into the system prompt at startup. Knowing it has a finite budget (e.g., 15 web searches, 10 URL fetches, 30 read operations), the agent plans strategically and conserves resources.

Adjusting these quotas involves a trade-off: tighter limits speed up execution but may cut tasks short, while looser limits allow deeper exploration at the cost of time and compute.

### Vibe Coding with Pi and Local Scaffolding
The actual implementation leverages the Pi coding agent alongside a custom `local agent builder` skill. This skill provides a structured scaffolding based on the Microsoft agent framework (though easily adaptable to LangChain or other frameworks) and includes extensive documentation, UI templates, session management, and tool definitions. 

Using the Pi agent for VS Code extension, a detailed prompt instructs the coding assistant to generate the three-tier architecture. Pi reads the scaffold, modifies `prompt.py` to define roles, capabilities, and rules for each tier, and updates `app.py` to wire the orchestrator, searcher, and analyzer together. The system is then deployed locally using `llama.cpp` with ROCm support. Initial testing runs the 27B Qwen 3.6 MTP model with Q4_K_XL quantization. During execution, the agent successfully breaks down a query about an Italian magician, delegates searches, fetches pages, and uses the `grep` tool to extract precise details. When the initial run omits source URLs in the final report, the prompt is iteratively refined, and Pi automatically patches the delegation logic to pass URLs back to the orchestrator.

### Benchmarking and Evaluating Performance
Building an agent is only half the work; rigorous evaluation is required to validate its reliability. The scaffold includes an evaluation harness that simplifies benchmarking. A custom dataset is created containing diverse queries, expected artifacts, and ground-truth answers. The harness uses an LLM-as-a-judge evaluation type to score outputs against weighted criteria.

By running each query multiple times (typically three iterations), the system collects average success rates and execution times. In this deployment, the agent achieved an aggregate score of 79.1%. The HTML results viewer highlights which compound queries succeeded, which failed, and where information was missing. This feedback loop is essential: it reveals edge cases, guides prompt optimization, and helps fine-tune tool quotas and concurrency settings. Switching to a more efficient model like the 35B parameter Qwen (with only 3B active parameters) alongside a concurrency level of five further optimizes throughput for the R9 7000 hardware.

### Summary
Constructing a deep research agent from scratch reveals the critical importance of architectural design over raw model size. By moving away from flat agents and adopting a three-tier delegation strategy, context pollution is eliminated, performance remains stable, and output quality improves significantly. Implementing tool quotas prevents infinite loops, while leveraging local coding assistants like Pi accelerates development without sacrificing control. Finally, integrating a structured evaluation harness with LLM-as-a-judge scoring transforms guesswork into data-driven iteration. This workflow not only produces a functional local research tool but also builds the foundational engineering skills necessary to adapt agentic architectures to any custom application. Future iterations can expand this foundation into agentic RAG systems that query pre-indexed local document libraries using semantic and keyword search.
