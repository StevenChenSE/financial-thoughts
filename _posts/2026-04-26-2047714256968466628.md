Building AI agents is exciting—but deploying them in production? That's where most projects stall. Ivan Ardyni, Developer Advocate at Google Cloud, recently walked through a comprehensive framework for building, evaluating, and scaling AI agents using Claude on Vertex AI. Here's everything you need to know.

## The Production Problem: Why AI Agents Are Hard to Scale

Before diving into solutions, Ardyni set the stage by acknowledging a harsh reality: while AI agents enable powerful applications in prototyping, productionalizing them remains extraordinarily difficult. He identified three core challenges:

- **Framework fragmentation**: The agent-building landscape is packed with frameworks, tools, and capabilities, making it difficult to integrate different systems and make them work together cohesively.

- **Cross-framework communication**: Even if you successfully build agents with one framework, enabling communication between agents built on different frameworks is a significant obstacle.

- **Operational complexity**: Once agents are built, managing them at scale requires robust monitoring, logging, and governance infrastructure that's notoriously challenging to implement.

These challenges prompted Google Cloud to define its own agent stack—a standardized approach that addresses all three pain points in a unified system.

## Google Cloud's Four-Component AI Agent Stack

Google Cloud's response to these challenges is a purpose-built agent stack comprising four main components:

### 1. Agent Development Kit (ADK)

The Agent Development Kit is an open-source, code-first, developer-friendly framework that enables you to build, evaluate, and deploy agents at scale. Key characteristics include:

- Designed for software engineering best practices
- Provides several pre-built agent types and patterns (including sequential agents)
- Supports the simplest pattern: the LLM Agent, which uses an LLM as the "brain" of the agent
- Requires you to configure the model, agent name, description, instructions, and available tools

### 2. MCP (Model Context Protocol) Compatibility

To standardize how agents communicate with different tools, ADK was built to be compatible with MCP. This protocol:

- Enables agents to consume tools and context through LLMs
- Makes agents compatible with several tools and applications
- Standardizes the way AI systems access external context and capabilities

### 3. Vertex AI Agent Engine

This is the managed platform designed specifically for deploying, managing, and scaling AI agents in production. Agent Engine:

- Handles all operational challenges associated with production deployment
- Provides built-in observability and monitoring capabilities
- Automatically collects interaction logs for evaluation and improvement
- Integrates with Vertex AI evaluation service for continuous agent optimization

### 4. Agent-to-Agent Protocol

An open-source protocol that enables seamless communication and collaboration between agents built with different frameworks, solving the cross-framework communication problem.

## Getting Started: Accessing Claude Through Vertex AI

Before building agents, you need to know how to access Claude models. Vertex AI provides several entry points:

- **Model Garden**: A centralized hub offering models from different providers, including Anthropic. You can find all Claude models here, including the latest releases.

- **Vertex AI Studio**: A prompt UI for testing models. You can select Claude 3.7 Sonnet (or other available Claude models) and start interacting with them directly, then use the API to integrate with your applications.

> **Note**: The team is actively integrating Claude 4 with ADK, with releases coming in the near future.

## Building Your First Agent with ADK

In the demo, Ardyni built a simple birthday planner agent to illustrate ADK's approach. The process is remarkably streamlined—creating an agent requires just three files:

1. **agent.py**: Contains the agent logic
2. **.env**: Contains environment variables
3. **__init__.py**: Standard Python package initialization file

The code itself is straightforward:

```python
# Import the LLM Agent class and Claude model
from google.adk.agents import LlmAgent
from google.adk.models import Claude

# Create your agent
agent = LlmAgent(
    name="birthday_planner",
    model=Claude(),  # Uses Claude 3.7 Sonnet by default
    description="Helps you plan birthday parties",
    instruction="You are a birthday planner assistant. Help users organize memorable birthday celebrations.",
)
```

Once defined, you can interact with the agent using the ADK CLI:

- **ADK run**: Starts an interactive session with your agent (e.g., `adk run birthday`)
- **ADK web**: Launches a web UI for visual interaction and debugging

This iterative workflow allows you to develop, test, and improve agents quickly. The design philosophy prioritizes simplicity—you can go from concept to running agent in minutes with just three files and one CLI command.

## Extending to Multi-Agent Systems with MCP

The real power emerges when you extend single agents into multi-agent systems. Ardyni demonstrated this by adding a calendar service agent that can schedule events in your agenda.

The architecture involved:

- **Birthday Planner Agent**: The original agent (can optionally use Gemini for certain tasks)
- **Calendar Agent**: Uses Claude 3.5 with an MCP server to handle scheduling
- **Orchestrator Agent**: Routes user requests to the appropriate agent based on intent

### How MCP Integration Works

ADK offers two ways to leverage MCP:

1. **Use existing MCP servers as tools**: Connect to any MCP server (pre-built or custom) and integrate it as a tool within your ADK agent
2. **Expose ADK-built tools via MCP**: If you've built tools in ADK, you can deploy them via MCP to interact with other agents

To integrate an MCP server, you only need a few lines of code:

```python
# Connect to an MCP server
mcp_server = McpServer(url="your-mcp-server-url")

# Create a connection
connection = mcp_server.create_connection()

# The MCP server automatically becomes available as a tool
```

When you run the agent, ADK automatically retrieves all requirements from the MCP server, converts it to a tool format, and integrates it seamlessly with your agent.

### Debugging with the ADK Web UI

ADK includes a built-in web UI that visually shows what's happening behind the scenes:

- See which agent is handling each request
- View the complete conversation flow
- Debug multi-agent interactions in real time

This visibility is crucial for understanding and optimizing complex agent workflows.

## Deploying Agents at Scale with Agent Engine

The final piece of the puzzle is production deployment. Ardyni explained why this step is traditionally complex:

**Without Agent Engine, deploying at scale requires you to:**

1. Package your agent code
2. Wrap it in a web framework (FastAPI, Django, etc.)
3. Build and manage containers
4. Configure infrastructure (GCP environment)
5. Handle operational concerns like monitoring and logging

**With Agent Engine, you simply:**

1. Provide the base requirements your agent needs to run
2. Use the Agent Engine create method
3. Your agent is live—with all observability, monitoring, and logging handled automatically

### What Agent Engine Provides

Agent Engine integrates with any agent framework (ADK, LangGraph, LangChain, and others), any tool system, and any model you choose. Once deployed, you automatically get:

- **Observability**: Real-time monitoring of agent behavior
- **Scalability**: Handle increased load without infrastructure management
- **Session management**: Built-in conversation state handling
- **Evaluation integration**: Connects to Vertex AI Evaluation Service for continuous improvement
- **Enterprise features**: Integration with Agent Space for business-context integration

The monitoring dashboard shows:

- Queries received by the agent
- Response latency
- CPU and memory utilization

This data helps you understand if you've allocated sufficient resources to serve your agents effectively at scale.

## Key Takeaways

1. **Production challenges are real but solvable**: Framework fragmentation, cross-framework communication, and operational complexity are the three main obstacles—and Google Cloud has built a complete stack to address them.

2. **ADK simplifies agent development**: With just three files and a CLI, you can build functional agents that integrate with Claude and other models through Vertex AI.

3. **MCP is the key to extensibility**: The Model Context Protocol standardizes tool integration, allowing you to connect any MCP server (or expose ADK tools) with minimal code.

4. **Multi-agent systems unlock new capabilities**: By combining specialized agents with an orchestrator, you can build sophisticated workflows that delegate tasks intelligently.

5. **Agent Engine removes deployment friction**: Stop managing infrastructure—Agent Engine handles deployment, observability, scaling, and evaluation so you can focus on building better agents.
